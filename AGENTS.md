# GSS-Bridge Multi-Agent Guide

This repository establishes a cross-agent protocol connecting **Spec-Kit**, **Graphify**, and **Superpowers** across multiple AI coding agents:
- **Claude Code** (`claude`)
- **OpenAI Codex** (`codex`)
- **Google Antigravity** (`antigravity` / `agy`)
- **Google Gemini CLI** (`gemini`)

---

## The Trinity Protocol

```
                           ┌──────────────────────────────┐
                           │      Spec-Kit (Governance)   │
                           │   specs/<feature>/           │
                           │   spec.md · plan.md · tasks  │
                           └──────────────┬───────────────┘
                                          │
                  ┌───────────────────────┴───────────────────────┐
                  ▼                                               ▼
   ┌──────────────────────────────┐                ┌──────────────────────────────┐
   │     Graphify (Context)       │◄──────────────►│    Superpowers (Discipline)  │
   │  graphify-out/graph.json     │   Scoping &    │  TDD · Subagents · Debugging │
   │  query · explain · path      │   Traceability │  Verification · Code Review  │
   └──────────────────────────────┘                └──────────────────────────────┘
```

1. **Spec-Kit Governance**:
   - `specs/<feature>/spec.md` (Requirements)
   - `specs/<feature>/plan.md` (Architecture & TDD strategy)
   - `specs/<feature>/tasks.md` (Canonical checklist & `[P]` tasks)
   - **Rule**: NEVER create external plans in `docs/plans/`. All TDD plans belong directly in `plan.md`.

2. **Graphify Context & Topology**:
   - `graphify-out/graph.json` (Knowledge graph generated by `/graphify`)
   - `graphify query "<topic>"`: Search concepts in domain vocabulary.
   - `graphify explain "<node>"`: Trace callers, callees, and compute blast radius for `plan.md`.
   - `graphify path "<nodeA>" "<nodeB>"`: Verify that tasks tagged `[P]` have no direct coupling or shared mutable state.
   - `graphify update .`: Run incremental sync upon completing implementation.
   - **Mandatory Knowledge Graph Pre-requisite & Auto-Initialization**: All commands and workflows requiring Graphify (`query`, `explain`, `path`, `blast-radius`, `bug-assess`, `dispatch`, `test-select`, `drift`, and architecture planning in `plan.md`) strictly require `graphify-out/graph.json`. If `graphify-out/graph.json` does not exist yet, the agent/command MUST execute `/graphify .` (or `graphify .`) to initialize and build the knowledge graph first before proceeding. Skipping, bypassing, or falling back to unguided file search when the graph is missing is strictly prohibited.
   - **Graphify Boundary & Exclusions**: Graphify knowledge graphs must index application codebase architecture only. All AI knowledge directories (`.specify/`, `.agents/`, `.claude/`, `.gemini/`, `.cursor/`, `.windsurf/`, `.kilo/`, `.devin/`, `.codex/`, `.copilot/`, `.ai/`) and Graphify internal processing artifacts (`graphify-out/`, `raw/`, `.graphify*`) MUST be strictly excluded via `.graphifyignore`.

3. **Superpowers Discipline**:
   - `test-driven-development`: Write failing test before writing implementation code.
   - `subagent-driven-development`: Dispatch subagents for independent `[P]` tasks, scoping each subagent ONLY to files identified by Graphify.
   - `systematic-debugging`: When tests fail, trace call hierarchies via `graphify path` before proposing fixes.
   - `verification-before-completion`: Run test suites and verify output before marking `- [x] T###`.
   - `requesting-code-review` & `finishing-a-development-branch`.

4. **The GSS-Bug Protocol**:
   - `speckit-gss-bridge-bug-assess`: Diagnoses bugs with Graphify AST context, computing upstream callers, downstream callees, blast radius, and visual Mermaid diagrams. Outputs canonical assessment to `.specify/bugs/<slug>/assessment.md`.
   - `speckit-gss-bridge-bug-fix`: Remediates bugs under strict Superpowers TDD discipline (reproduction test RED $\rightarrow$ fix GREEN $\rightarrow$ REFACTOR), test verification, automatic `graphify update .`, and canonical closure in `.specify/bugs/<slug>/fix.md`.

5. **Automated Subagent Wave Dispatcher & The Iron Law of Subagent Dispatch**:
   - `speckit-gss-bridge-dispatch`: Automatically partitions `[P]` tasks in `tasks.md` into execution waves based on pairwise topological graph distance ($d \ge 3$), generating subagent prompts strictly scoped to 1-2 hop AST neighborhoods.
   - **Mandatory Automated Dispatch Mandate**: When executing implementation tasks (`/gss-bridge` or `/speckit-gss-bridge-execute`), if `tasks.md` contains `[P]` tasks, the agent MUST run `dispatch-subagents.ps1 -Json` (or `.sh --json`) and MUST dispatch subagents in parallel for each wave (`invoke_subagent` for Antigravity with `Model: 'inherit'`, `TypeName: 'self'`, `Prompt: task.subagent_prompt`). Sequential or inline execution of `[P]` tasks in the parent session is strictly prohibited.

6. **GSS-Teamwork Protocol (Autonomous Multi-Agent Teams)**:
   - `speckit-gss-bridge-teamwork`: Unites Antigravity `/teamwork` with the Trinity Protocol, deploying a 3-role matrix:
     1. **Lead Orchestrator**: Manages state in `.specify/gss-handoff.json` and orchestrates waves.
     2. **Coder Subagents**: Execute parallel tasks in isolated Git worktrees (`.specify/worktrees/`) with AST-pruned skeletons and strict TDD.
     3. **Sentinel Reviewer**: Independent adversarial verification gate running `test-impact.ps1` and `drift-detector.ps1` before approving worktree merge.
   - Script: `teamwork-plan.ps1 -Json` / `teamwork-plan.sh --json` outputs the full team roster and verification commands.

7. **Advanced Architecture & Concurrency Optimizations**:
   - `speckit-gss-bridge-prune`: Extracts AST structural skeletons, saving 70–80% of subagent prompt tokens.
   - `speckit-gss-bridge-test-select`: Graph-guided Test Impact Analysis (TIA) to identify test suites affected within 1–2 hops.
   - `speckit-gss-bridge-drift`: Audits knowledge graph for architectural drift, layer boundary violations, and circular dependencies.
   - `speckit-gss-bridge-repro-gen`: Auto-synthesizes minimal failing reproduction test cases (RED) during bug triage.
   - `speckit-gss-bridge-decision`: Persistent journal of cross-agent architectural trade-offs in `.specify/agent-decisions.jsonl`.
   - `speckit-gss-bridge-dashboard`: Interactive standalone HTML cockpit at `.specify/dashboard/index.html`.
   - `speckit-gss-bridge-worktree`: Manages isolated git worktrees (`.specify/worktrees/`) for parallel subagent waves.

8. **Line Ending & Portability Discipline**:
   - All structural files, manifests, templates, docs, data, and PowerShell scripts (`.md`, `.yml`, `.yaml`, `.json`, `.jsonl`, `.ps1`, `.py`) must strictly use **CRLF (`\r\n`)** line endings.
   - All POSIX shell scripts (`*.sh`) must strictly use **LF (`\n`)** line endings without carriage returns (`\r`) for cross-platform execution on Linux (`ubuntu-latest`) and macOS (`macos-latest`).
   - `.gitattributes` enforces `* text=auto eol=crlf` and `*.sh text eol=lf` across all assets.

## Shared Handoff Contract (`.specify/gss-handoff.json`)

All agents read and transition the same state machine:
- `ready`: Spec-Kit has initialized feature; waiting for planning and tasks.
- `executing`: Superpowers + Graphify are driving implementation.
- `blocked`: Contract gap discovered; design artifacts need repair.
- `complete`: All tasks verified, code reviewed, graph updated.

Dual writes to `.specify/superpowers-handoff.json` ensure backwards compatibility with legacy tooling.
